How it works

One WebSocket. The key never leaves the server.

Browser headset app

  • Mic → AudioWorklet → PCM16 @ 24 kHz
  • Ring-buffer playback, flushed on server-confirmed barge-in
  • Shift state machine runs the client-side tools
  • Floor map, captions, shift-lead desk
input.audio⇄reply.audiotool.calltool.resultsession.update

AssemblyAI Voice Agent API

  • Universal-3 Pro streaming speech-to-text, keyterms
  • Semantic turn detection and barge-in
  • LLM with JSON-Schema tool calling
  • Voices: alba, lola, juergen, estelle, giovanni, rafael
  • voice_focus far-field for a noisy floor

Node server

  • Mints single-use tokens (GET /v1/token), rate-limited
  • Session cap, 15 min

Sessions API

  • Recording + conversation timeline for every shift
  • Shift report and audit trail for every pick

🔒
session.update swaps the prompt and tools on every transition. confirm_pick doesn't exist until the slot is verified, so Tote can't log a pick at the wrong slot.
🔢
The model picks the intent; code reads the value. Check digits and counts are parsed from the Universal-3 Pro transcript, never generated by the LLM. A check digit can't be hallucinated.
